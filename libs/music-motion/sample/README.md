# The dataset of the animation screens

A small, real dataset that the in-memory adapter and the mock load, and that can be imported from a file: songs, pieces in
different states, references, styles and parts, with one real video. Everything that is not the video (design, script, song map,
the analysis of a reference) is made by the fixed rules the adapter and the mock already use for a new piece; a finished piece
plays `sample.mp4`.

- `sample.mp4` — 12 s, 1280x720, 30 fps, with sound. Everything in it is generated by `ffmpeg` filters (gradients, a box that pulses
  on the beat, a synthesized kick and hat at 96 bpm), so nobody holds rights to it. Regenerate it with `npm run sample:video`
  (needs `ffmpeg`; the committed file is the truth).
- `sample.json` — the dataset. It is written by `npm run sample:dataset` (`scripts/make-sample-dataset.mjs`): edit the descriptors
  there, not the file. It is also what `npm run sample:sync` updates with the facts of the video.

## The format

```jsonc
{
  "songs":      [{ "project": "p", "trackId": "track-1", "variant": 0, "title": "…", "seconds": 12, "bpm": 96, "instrumental": false, "lyrics": "[Verse]\n…" }],
  "pieces":     [{ "id": "…", "song": { "project": "p", "trackId": "track-1", "variant": 0 }, "level": "simple|medium|advanced",
                   "style": "typographic|illustrated", "fps": 24|30|60, "resolution": "1280x720", "state": "done|draft|failed", "error": "only when failed" }],
  "references": [{ "id": "…", "title": "…", "notes": "…", "tags": ["…"], "source": "https://www.youtube.com/watch?v=…" }],
  "presets":    [{ "id": "…", "name": "…", "referenceId": "id of a reference above" }],
  "parts":      [{ "name": "kebab-case", "description": "…", "manifest": { "name": "…", "version": 1, "levels": [], "params": [] }, "fragment": "<style>…</style>…<script>…</script>" }],
  "video":      { "file": "sample.mp4", "address": "samples/music-motion/sample.mp4", "seconds": 12, "bytes": 392476, "width": 1280, "height": 720 }
}
```

Pieces name their song by project, track and version, and styles name their reference, so every name must exist in the file.
A part may carry its text: a `manifest` (what `manifest.json` says) and a `fragment` (`part.html`), both or none; the three of the sample do, so the browser can draw them (`@lab/motion-editor`), and the in-memory adapter and the mock read them back (`partText`, `GET /api/music-motion/parts/{name}`). The fragments follow the part contract (`window.__params`, `window.__partSeek(t, beat)`, no wall clock, no random numbers, nothing from outside) and are written in `scripts/make-sample-dataset.mjs`. Ids are unique inside each list; a part's name must not be one the catalog already has. `songs`, `pieces`, `references`, `presets` and
`parts` may each be empty or missing. The video facts are only needed by the built-in dataset.

## Importing a file

In memory mode (`?adapter=memory`) the Pieces screen has **Import dataset**: choose a `.json` in this format. A valid file is loaded
like the built-in one (an item whose id is already there is replaced by the file's; the rest and what you made yourself stay); an
invalid one changes nothing and says why. The file is read in the browser and sent nowhere.

## Putting a real render in its place

Render a piece with the real server, save its video as `sample.mp4` here (same name) and run `npm run sample:sync`: it reads the
file with `ffprobe` and rewrites the length, size and dimensions in `sample.json` (every song lasts as long as the video). Nothing
else refers to what the video shows. Keep it small: the public repository carries it.
